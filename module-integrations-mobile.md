## Partial cross-layer findings

* Admin integration health GET accepts `range` in `1h|24h|7d|30d`, defaults invalid values to `24h`, returns private cache headers; POST runs safe checks and is idempotent. Evidence: `src/app/api/v1/integrations/health/route.ts:8-34`.
* LTI 1.3 login initiation accepts GET/POST parameters `iss` URL, `login_hint` 1–2048, `target_link_uri` URL max 2048, optional `lti_message_hint` max 4096, optional client/deployment IDs max 512. It resolves a registered platform, checks client ID, generates state/nonce, stores single-use launch state with 10-minute TTL, then redirects to platform authorization. Authorization validates JWT signature/issuer/audience, consumes state, checks nonce/replay, and decides whether to link/create/deny user. Evidence: `src/app/api/v1/lti/login/route.ts:16-60+`, `src/app/api/v1/lti/authorize/route.ts`, `src/lib/lti/launch-security.ts`.
* Mux webhook requires `MUX_WEBHOOK_SECRET`, verifies `mux-signature`, rejects invalid signature with 401, malformed JSON with 400, missing config with 503. `video.live_stream.active` moves scheduled/live session to live; idle only completes a currently live session; ready/completed asset events store public HLS recording URL. Unknown events are acknowledged as received/handled false. Evidence: `src/app/api/v1/webhooks/mux/route.ts:24-93+`.
